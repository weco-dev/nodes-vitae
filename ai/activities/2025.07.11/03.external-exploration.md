## Dependency Analysis

### SurveyJS Integration Assessment

**✅ STRONGLY RECOMMENDED** - SurveyJS is an excellent choice for this project
based on the research:

**Pros for this project:**

- **Perfect Feature Match**: Supports all required question types (multiple
  choice, text input, rating scales, yes/no)
- **Typeform-like UI**: Built-in support for one-question-per-page layouts with
  progress indicators
- **State Management**: Handles complex form state, validation, and progress
  tracking automatically
- **Development Speed**: Significantly reduces development time vs custom
  implementation
- **React Integration**: Native React support with TypeScript compatibility
- **Customization**: Extensive theming and styling options to match existing
  design system
- **JSON-driven**: Questions can be easily moved from hardcoded to database
  later

**Concerns addressed:**

- **SSR Limitation**: SurveyJS doesn't support server-side rendering, but this
  can be handled in Remix with client-side components
- **Bundle Size**: Adds ~200KB, but saves weeks of development time
- **Learning Curve**: Well-documented with React examples

**Alternative considerations:**

- **React Hook Form + Custom Components**: Would require significant development
  effort for Typeform-like UI
- **Custom Implementation**: Would take 3-4x longer to achieve the same
  functionality

# ESG Assessment Feature - Complete Development Brief

## Project Context

You're building the first feature for an ESG (Environmental, Social, and
Governance) assessment platform for the wine industry. The platform already has
user authentication, but you need to build the complete assessment system from
scratch.

## Technical Stack & Approach

- **Framework**: Remix with React
- **Form Library**: SurveyJS Form Library for React
- **State Management**: Remix forms with server actions + SurveyJS client state
- **UI Components**: SurveyJS components + Shadcn components for
  navigation/layout
- **Question Storage**: Hardcoded questions initially (5 test questions)
- **Database**: Create new data models for assessments (user auth already
  exists)

## Assessment Features & Business Logic

### Core Assessment Flow

- **SurveyJS Pages**: One question per page (configured in JSON)
- **Navigation**: SurveyJS built-in Previous/Next buttons
- **Progress**: SurveyJS progress bar component
- **State Persistence**: Save SurveyJS survey data on page changes
- **Completion**: Use SurveyJS onComplete event

### SurveyJS Event Handling

```typescript
survey.onCurrentPageChanged.add((sender) => {
	// Save progress when moving between pages
	saveSurveyProgress(sender.data)
})

survey.onComplete.add((sender) => {
	// Handle assessment completion
	completeAssessment(sender.data)
})

survey.onValueChanged.add((sender, options) => {
	// Track individual answer changes
	saveAnswer(options.name, options.value)
})
```

### User Capabilities

- Start new assessment (only if no open assessment exists)
- Save and pause current assessment using SurveyJS state
- Resume previous open assessment by restoring SurveyJS state
- Complete assessment (SurveyJS onComplete event)
- View past completed assessments
- Delete/cancel open assessment
- Archive completed assessment
- Navigate back/forward through questions (SurveyJS navigation)

### Business Rules

- **Max open assessments**: 1 per user
- **Assessment states**: open → completed → archived
- **Scoring**: Calculate from SurveyJS data + question weights
- **Validation**: SurveyJS built-in required field validation

## Technical Implementation Notes

### Remix + SurveyJS Integration

```typescript
// app/routes/assessment.take.tsx
export default function AssessmentTake() {
  const assessment = useLoaderData<typeof loader>();

  return (
    <ClientOnly fallback={<AssessmentSkeleton />}>
      {() => <SurveyComponent initialData={assessment.surveyData} />}
    </ClientOnly>
  );
}

// Use action for saving progress
export async function action({ request }: ActionFunctionArgs) {
  const formData = await request.formData();
  const surveyData = JSON.parse(formData.get("surveyData") as string);

  // Save to database
  await saveAssessmentProgress(surveyData);

  return json({ success: true });
}
```

### Data Flow

1. User clicks "Start/Continue Assessment"
2. Load assessment state from database
3. Initialize SurveyJS with saved state
4. SurveyJS handles question display and navigation
5. Save progress via Remix actions on page changes
6. Use SurveyJS onComplete for final submission

### Error Handling

- SurveyJS built-in validation for required questions
- Remix error boundaries for server errors
- Custom confirmation dialogs for leaving assessment
