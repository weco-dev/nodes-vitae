# ESG Assessment Feature - Complete Development Brief

## Project Context

You're building the first feature for an ESG (Environmental, Social, and
Governance) assessment platform for the wine industry. The platform already has
user authentication, but you need to build the complete assessment system from
scratch.

## Technical Stack & Approach

- **Framework**: Remix with React
- **State Management**: Remix forms with server actions
- **UI Components**: Shadcn components (especially Accordion)
- **Question Storage**: Hardcoded questions initially (5 test questions)
- **Database**: Create new data models for assessments (user auth already
  exists)

## Data Models to Create

### Assessment Model

```
- id (unique identifier)
- userId (foreign key to existing user)
- status: "open" | "completed" | "archived"
- currentQuestionIndex (number, for resume functionality)
- createdAt, updatedAt
- completedAt (nullable)
```

### AssessmentAnswer Model

```
- id
- assessmentId (foreign key)
- questionId (string, matches hardcoded question IDs)
- answer (JSON field to store different answer types)
- createdAt, updatedAt
```

## Question Structure (Hardcoded)

Each of the 5 test questions should have:

```typescript
{
  id: string; // unique identifier
  section: string;
  title: string;
  descriptions: string[]; // max 3 items for Accordion
  type: "multiple_choice" | "text_input" | "rating_scale" | "yes_no";
  options?: string[]; // for multiple choice (multiple selections allowed)
  score: number; // for scoring calculations
  mandatory: boolean; // all true for now
}
```

## Question Types Implementation

1. **Multiple Choice**: Checkboxes (multiple selections allowed)
2. **Text Input**: Basic text field (no validation/limits for now)
3. **Rating Scale**: Star component (1-10 range)
4. **Yes/No**: Radio buttons

## Assessment Features & Business Logic

### Core Assessment Flow

- **One question per screen** (Typeform-style)
- **Fixed question order** (users cannot jump to random questions)
- **Navigation**: Previous/Next buttons only
- **Progress saving**: Manual save when moving between questions (if answer
  changed)
- **Completion**: Assessment complete when all mandatory questions answered
- **Resume**: Users resume from where they left off

### User Capabilities

- Start new assessment (only if no open assessment exists)
- Save and pause current assessment
- Resume previous open assessment
- Complete assessment (explicit button click required)
- View past completed assessments
- Delete/cancel open assessment
- Archive completed assessment
- Navigate back/forward through questions freely
- Review/summary page before final submission

### Business Rules

- **Max open assessments**: 1 per user
- **Assessment states**: open → completed → archived
- **Scoring**: Simple sum of answered questions × their weights
- **Validation**: All mandatory questions must be answered to complete

## UI/UX Requirements (Typeform-inspired)

### Visual Design

- One question per full-screen view
- Clean, minimalist interface with white space
- Readable typography for questions
- Center-aligned question display
- Thin progress bar at top
- Subtle animations and smooth transitions

### Question Display

- Question title prominently displayed
- Descriptions in Shadcn Accordion component (max 3 items)
- Answer options visually distinct and easy to target
- Previous/Next navigation buttons
- Question numbering/progress indicators

### Responsive Design

- Works seamlessly across devices
- Touch-friendly interface on mobile
- No special mobile gestures needed initially

## Navigation Integration

### Sidebar Updates (`@app/components/app-sidebar.tsx`)

- **Quick Create Button**:
  - Shows "Start Assessment" when no open assessment
  - Shows "Continue Assessment" when paused assessment exists
- **Assessment Menu**:
  - List last 3 assessments
  - Link to full assessment history page

### Page Structure Needed

- Assessment taking page (`/assessment/take`)
- Assessment history page (`/dashboard/assessments`)
- Assessment summary/review page (`/dashboard/assessment/[id]/summary`)

## Technical Implementation Notes

### Remix Patterns

- Use Remix forms with server actions for question submissions
- Implement loader functions for assessment data
- Use Remix's built-in form validation and error handling
- Handle navigation with Remix's redirect responses

### Data Flow

1. User clicks "Start/Continue Assessment"
2. Load assessment state from database
3. Display current question with form
4. On Previous/Next click, save answer (if changed) and navigate
5. Track progress and validate completion status
6. Show review page when all mandatory questions answered

### Error Handling

- Confirmation dialog when trying to leave incomplete assessment
- Validation for mandatory questions
- Graceful handling of navigation edge cases

This brief provides all the technical detail and business logic needed for a
junior developer to implement the complete ESG assessment feature.
