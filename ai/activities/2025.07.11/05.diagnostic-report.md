# ESG Assessment Feature - Diagnostic Report

## Summary of the Issue

The project requires building a comprehensive ESG (Environmental, Social, and Governance) assessment platform for the wine industry. This is a greenfield feature development that needs to integrate with an existing Epic Stack application that already has user authentication. The system must support a complete assessment workflow using SurveyJS Form Library with specific integration requirements for question identification, section grouping, and accordion descriptions.

## Relevant Modules and Components

### Core Application Areas
- **Route Structure**: `/app/routes/` - New assessment routes need integration
  - Assessment fill-in routes under `/assessment` root
  - Dashboard assessment routes under `/dashboard` 
- **Database Layer**: `/prisma/` - New data models required
  - Assessment model with SurveyJS state persistence
  - AssessmentAnswer model with question tracking
- **Authentication System**: `/app/utils/auth.server.ts` - Integration required for user access control
- **UI Components**: `/app/components/` - New assessment-specific components needed
- **Server Utilities**: `/app/utils/` - Assessment business logic and data handling

### External Dependencies Integration
- **SurveyJS Integration**: New dependency requiring client-side rendering approach
  - `survey-react-ui` and `survey-core` packages
  - Client-only component pattern due to SSR limitations
- **Shadcn UI Components**: `/app/components/ui/` - Accordion component for question descriptions
- **Remix Framework**: Server-side data handling and form processing

## Implicated Code Paths

### Assessment Creation and Management Flow
1. **User Access**: `auth.server.ts` → User authentication validation
2. **Route Handling**: `/assessment` routes → SurveyJS component initialization
3. **Data Persistence**: Database models → SQLite JSON storage for survey state
4. **State Management**: SurveyJS events → Remix actions for progress saving
5. **Navigation**: App sidebar updates → Assessment status and quick actions

### Question Rendering and Interaction Flow
1. **Question Configuration**: Hardcoded questions → SurveyJS JSON schema transformation
2. **Custom Component Integration**: SurveyJS `onAfterRenderQuestion` → Shadcn accordion injection
3. **Answer Tracking**: SurveyJS `onValueChanged` → Database answer storage with question ID and section
4. **Progress Tracking**: SurveyJS `onCurrentPageChanged` → Assessment state updates

### Data Flow Architecture
1. **Client-Server Communication**: Remix loaders/actions ↔ SurveyJS client state
2. **Database Operations**: Prisma ORM → SQLite with JSON field support
3. **State Persistence**: SurveyJS survey data → JSON TEXT storage with validation

## Impact Assessment

### High Impact Areas
- **Database Schema**: New tables and relationships required (Assessment, AssessmentAnswer models)
- **Route Structure**: Significant expansion with dedicated assessment and dashboard routes
- **Authentication Integration**: Access control for assessment features
- **Client-Side Rendering**: Introduction of client-only components in SSR framework

### Medium Impact Areas
- **UI Component Library**: Extension with assessment-specific components
- **Navigation System**: App sidebar modifications for assessment access
- **Server Actions**: New Remix actions for assessment data handling
- **Build Configuration**: New dependencies and potential bundle size impact

### Low Impact Areas
- **Existing User System**: Minimal changes, leveraging existing authentication
- **Core Epic Stack Features**: No modifications to existing functionality
- **Development Workflow**: Standard Epic Stack patterns maintained

## Key Observations

### Technical Challenges
1. **SSR Compatibility**: SurveyJS doesn't support server-side rendering, requiring client-only component pattern with lazy loading
2. **Custom Component Integration**: Complex DOM manipulation required for Shadcn accordion integration within SurveyJS rendering cycle
3. **State Persistence**: Managing SurveyJS client state with Remix server-side form handling
4. **JSON Storage**: SQLite JSON field validation and querying for survey data

### Architecture Considerations
1. **Route Separation**: Clear separation between assessment-taking (`/assessment`) and management (`/dashboard`) workflows
2. **Data Model Design**: Assessment and AssessmentAnswer models designed for SurveyJS integration with question tracking
3. **Business Logic**: One open assessment per user rule, state transitions (open → completed → archived)
4. **Custom Properties**: Question identification and section grouping through SurveyJS custom properties

### Integration Requirements
1. **Question Structure**: Unique identifiers, section grouping, and accordion descriptions (max 3)
2. **UI Consistency**: SurveyJS theming to match existing design system
3. **Progress Tracking**: Page-level progress persistence and resume capability
4. **Error Handling**: SurveyJS validation integration with Remix error boundaries

### Development Dependencies
- New packages: `survey-react-ui`, `survey-core`
- Database migrations for new assessment models
- Custom CSS for SurveyJS theming
- Client-side React component patterns for SSR framework
