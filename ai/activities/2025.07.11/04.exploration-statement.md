# ESG Assessment Feature - Integrated Development Brief

## Project Context

You're building the first feature for an ESG (Environmental, Social, and
Governance) assessment platform for the wine industry. The platform already has
user authentication, but you need to build the complete assessment system from
scratch.

## Key Integration Requirements

- **Assessment fill-in**: `/assessment` root route with its own layout
- **Other assessment pages**: `/dashboard` root route
- **Question identifiers**: Every question has a unique identifier
- **Section grouping**: Every question is grouped in sections (string) that is
  visible in every question
- **Question descriptions**: Must be an accordion with max 3 descriptions (one per accordion item)

## Technical Stack & Approach

- **Framework**: Remix with React
- **Form Library**: SurveyJS Form Library for React
- **State Management**: Remix forms with server actions + SurveyJS client state
- **UI Components**: SurveyJS components + Shadcn components for
  navigation/layout
- **Question Storage**: Hardcoded questions initially (5 test questions)
- **Database**: Create new data models for assessments (user auth already
  exists)

## Database Considerations

### SQLite JSON Support

- **surveyData field**: `Record<string, any>` is fully supported in SQLite as JSON TEXT
- **JSON Functions**: SQLite 3.38+ includes JSON1 extension for querying JSON data
- **Storage**: JSON objects stored as TEXT with automatic validation
- **Querying**: Use `json_extract()`, `json_set()`, `json_valid()` functions

Example SQLite schema:
```sql
CREATE TABLE assessments (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  status TEXT CHECK(status IN ('open', 'completed', 'archived')),
  current_page_index INTEGER DEFAULT 0,
  survey_data TEXT CHECK(json_valid(survey_data)), -- JSON validation
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  completed_at DATETIME
);
```

## Custom Components Integration

### Accordion Description Component

The custom accordion component integration works by extending SurveyJS's rendering system to display question descriptions as Shadcn accordions.

**Problem**: SurveyJS doesn't natively support accordion UI for descriptions
**Solution**: Use SurveyJS's `onAfterRenderQuestion` event to inject custom React components

#### Technical Implementation

```typescript
// 1. Custom React Component (using Shadcn)
import { Accordion, AccordionContent, AccordionItem, AccordionTrigger } from '@/components/ui/accordion'

function QuestionAccordion({ descriptions }: { descriptions: string[] }) {
  const limitedDescriptions = descriptions.slice(0, 3) // enforce max 3
  
  return (
    <Accordion type="single" collapsible className="w-full">
      {limitedDescriptions.map((desc, index) => (
        <AccordionItem key={index} value={`item-${index}`}>
          <AccordionTrigger>More Info {index + 1}</AccordionTrigger>
          <AccordionContent>{desc}</AccordionContent>
        </AccordionItem>
      ))}
    </Accordion>
  )
}

// 2. SurveyJS Integration Hook
survey.onAfterRenderQuestion.add((sender, options) => {
  const question = options.question
  
  // Check if question has descriptions array
  if (question.descriptions && Array.isArray(question.descriptions)) {
    const accordionContainer = document.createElement('div')
    accordionContainer.className = 'question-accordion-wrapper'
    
    // Render React component into DOM
    ReactDOM.render(
      <QuestionAccordion descriptions={question.descriptions} />,
      accordionContainer
    )
    
    // Insert after question title, before answer options
    const questionTitle = options.htmlElement.querySelector('.sv_q_title')
    if (questionTitle) {
      questionTitle.insertAdjacentElement('afterend', accordionContainer)
    }
  }
})
```

#### Rendering Flow

1. **SurveyJS renders question** → Standard title, choices, etc.
2. **onAfterRenderQuestion fires** → Custom hook detects `descriptions` property
3. **React component created** → Shadcn accordion with max 3 items
4. **DOM injection** → Accordion inserted below question title
5. **User interaction** → Native accordion expand/collapse behavior

#### Benefits

- **Seamless integration**: Looks native to SurveyJS
- **Shadcn styling**: Matches your design system
- **Responsive**: Works on mobile/desktop
- **Accessible**: Shadcn accordions include ARIA attributes
- **Flexible**: Easy to modify accordion styling/behavior
