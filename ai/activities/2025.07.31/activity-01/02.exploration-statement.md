# **PROJECT BRIEF: ESG Assessment Demo Implementation**

## **Overview**
Create a standalone demo version of the ESG Assessment system that allows unauthenticated users to experience the assessment workflow with a curated set of 25 questions across all 7 ESG sections.

## **Target Developer Level**
Junior Full-Stack Developer (Remix + React experience required)

---

## **SCOPE & REQUIREMENTS**

### **Core Features**
1. **Demo Route**: Create `app/routes/_demo+/` route structure
2. **Demo Questions**: 25 questions across all 7 ESG sections with umbrella question support  
3. **Excel Import**: Separate import script for demo questions from Excel file
4. **Session Persistence**: Use localStorage for demo progress (no database)
5. **Full UI Reuse**: Same sophisticated UI as main assessment (progress bars, navigation, help system)
6. **Landing Page Integration**: Add "Try Demo" call-to-action button
7. **Analytics Tracking**: Track demo usage separately from authenticated assessments
8. **Mock Results**: Completion screen with mock summary/results

### **Technical Architecture**
- **Route Structure**: `app/routes/_demo+/take.tsx` (standalone, not under marketing)
- **Data Storage**: Browser localStorage for session persistence
- **UI Components**: Reuse existing assessment components (SurveyComponent, AssessmentNavigation, etc.)
- **Question Management**: Separate demo questions file (`app/utils/demo-questions.ts`)
- **Import Script**: `scripts/import-demo-questions.ts` (similar to existing import script)

---

## **DEMO APPROACH ANALYSIS & RECOMMENDATION**

### **Option A: Standalone `/demo` Route (RECOMMENDED ✅)**

**PROS:**
- ✅ Clean separation of concerns - demo logic isolated from production code
- ✅ No database pollution or cleanup requirements  
- ✅ Better performance - no authentication overhead
- ✅ Simpler security model - no user creation needed
- ✅ Clear analytics distinction between demo vs. real usage
- ✅ localStorage persistence works perfectly for session-based demo
- ✅ Can reuse all UI components while keeping data flow simple

**CONS:**
- ❌ Some code duplication for demo-specific logic
- ❌ Need to create separate question management system
- ❌ Slightly more initial development work

### **Option B: Auto-Generated Users**

**PROS:**  
- ✅ 100% code reuse from existing assessment system
- ✅ Complete feature demonstration

**CONS:**
- ❌ Database pollution with temporary users/assessments
- ❌ Complex cleanup logic needed 
- ❌ Security considerations for auto-authentication
- ❌ Analytics contamination
- ❌ Potential performance impact from database operations

### **FINAL RECOMMENDATION: Option A (Standalone Demo)**

Based on the requirements (25 questions, session persistence, no autosave needed), Option A is the better choice because:

1. **Cleaner Architecture**: Keeps demo separate from production
2. **Better Performance**: No database operations during demo
3. **Simpler Maintenance**: No cleanup logic required
4. **Analytics Clarity**: Clean separation of demo vs. real usage
5. **Security**: No temporary user creation needed

The code reuse is still significant - we can reuse all UI components (SurveyComponent, AssessmentNavigation, etc.) while just changing the data flow to use localStorage instead of database.

#### **2.3 Main Demo Route (take.tsx)**  
- **Based on**: `app/routes/assessment+/take.tsx`
- **Key Modifications**:
  - **Remove**: All authentication logic (`requireUserId` calls)
  - **Remove**: Database operations (loader/action database calls)
  - **Add**: localStorage-based state management
  - **Add**: Demo-specific analytics tracking
  - **Keep**: All UI components and user experience patterns

**Loader Function**:
```typescript
export async function loader() {
  const surveyJson = convertDemoToSurveyJsFormat(demoAssessmentQuestions)
  const demoData = getDemoDataFromLocalStorage()
  
  return {
    assessment: {
      id: 'demo',
      currentPageIndex: demoData.currentPageIndex || 0,
      surveyData: demoData.surveyData || {},
    },
    surveyJson,
    questions: demoAssessmentQuestions.map(q => ({
      questionId: q.questionId,
      section: q.section,
      title: q.title,
      isRequired: q.isRequired,
      type: q.type,
      parentQuestionId: q.parentQuestionId,
    })),
  }
}
```

**Action Function**:
```typescript  
export async function action({ request }: Route.ActionArgs) {
  const formData = await request.formData()
  const intent = formData.get('intent')
  
  switch (intent) {
    case 'save-progress': {
      // Save to localStorage instead of database
      saveDemoProgressToLocalStorage(surveyData, currentPageIndex)
      return { success: true }
    }
    case 'save-answer': {
      // Save individual answer to localStorage
      saveDemoAnswerToLocalStorage(questionName, answer)
      return { success: true }
    }
    case 'complete': {
      // Mark demo as completed and redirect
      completeDemoInLocalStorage()
      return redirect('/_demo/complete')
    }
  }
}
```
