# Comprehensive Diagnostic Report: ESG Assessment UI Issues

## 1. Summary of the Issue

The ESG assessment platform is experiencing several UI/UX issues that impact
user navigation and the overall assessment experience. The problems center
around the progress bar layout, missing section navigation capabilities, scroll
behavior, state management, and display of question descriptions. These issues
affect both mobile and desktop users across all 88 assessment questions spanning
7 sections.

## 2. Relevant Modules and Components

### Core Assessment Components

- **`app/components/assessment/responsive-progress-bar.tsx`** (318 lines)
  - Current implementation uses different layouts for mobile vs desktop
  - Desktop shows grid layout with `flex-wrap` causing multi-row display
  - Mobile uses horizontal scroll which works correctly
  - Contains progress calculation logic and navigation handlers

- **`app/components/assessment/survey-component.tsx`** (599 lines)
  - SurveyJS wrapper with accordion injection logic
  - Complex lifecycle management with React roots
  - Description injection mechanism in `onAfterRenderQuestion` handler
  - Real-time persistence and state management

- **`app/components/assessment/section-display.tsx`** (102 lines)
  - Simple display component showing current section and progress
  - No navigation capabilities - purely informational
  - Uses static layout without dropdown functionality

### Route Integration

- **`app/routes/assessment+/take.tsx`** (667 lines)
  - Main assessment route integrating all components
  - Handles state management and navigation logic
  - Uses `assessment.currentPageIndex` for progress tracking
  - Implements callbacks for progress bar navigation

### Data Layer

- **`app/utils/assessment-questions.ts`** (1800 lines)
  - Contains all 88 ESG questions across 7 sections
  - Question structure includes `descriptions` arrays for help content
  - Conversion utility `convertToSurveyJsFormat()` for SurveyJS integration
  - Section organization: SEZIONE 0, SEZIONE I through SEZIONE VI

## 3. Implicated Code Paths

### Progress Bar Layout Issues

**Problem Path**: Desktop Layout Logic

- `ResponsiveProgressBar` component lines 263-314 (desktop layout)
- Uses `flex-wrap` causing dots to wrap into multiple rows
- Grid layout implementation conflicts with single-row requirement

**Affected Code Block** (lines 263-314):

```tsx
<div className="flex flex-1 flex-wrap justify-center gap-2">
	{questions.map((question, index) => {
		// Progress dot rendering logic
	})}
</div>
```

### Section Navigation Missing

**Problem Path**: Static Section Display

- `SectionDisplay` component provides only visual feedback
- No dropdown or navigation capabilities
- Takes `section`, `currentQuestion`, `totalQuestions` as props
- No integration with navigation callbacks

### Auto-scroll Behavior

**Problem Path**: Navigation Without Scroll Management

- `ResponsiveProgressBar` handles `onPageChange` but lacks scroll logic
- No `scrollIntoView()` implementation for current dot visibility
- Navigation methods (`handlePrevious`, `handleNext`) don't ensure visibility

### State Navigation Issues

**Problem Path**: Initial Page Load Logic

- `take.tsx` route uses `assessment.currentPageIndex` from server
- No logic to navigate to last answered question on component mount
- Survey component initializes at index 0 regardless of progress

### Description Display Problems

**Problem Path**: Accordion Injection Logic

- `survey-component.tsx` lines 495-545 contain injection logic
- `onAfterRenderQuestion` handler attempts DOM manipulation
- Complex React root management for accordion components
- Console logging suggests validation issues with `question.descriptions`

## 4. Impact Assessment

### User Experience Impact

- **High Impact**: Desktop users see fragmented progress visualization (3 rows
  vs 1 row)
- **Medium Impact**: Users cannot quickly navigate between sections
- **Medium Impact**: Progress dots may be hidden during navigation
- **Low Impact**: Users return to question 1 instead of last answered
- **Low Impact**: Help content not displaying properly

### Technical Debt Impact

- **Layout Inconsistency**: Different patterns for mobile vs desktop
- **Component Coupling**: Progress bar tightly coupled to specific layout
  patterns
- **State Management**: Inconsistent handling of current page state
- **DOM Manipulation**: Complex React root management for accordions

### Performance Impact

- **Rendering**: Multiple React roots created for accordion injection
- **Memory**: Potential memory leaks from improper root cleanup
- **Navigation**: Inefficient re-rendering on progress bar updates

## 5. Key Observations

### Architecture Strengths

- Well-structured component hierarchy with clear separation of concerns
- Comprehensive TypeScript interfaces and documentation
- Robust error handling and loading states
- Real-time persistence with optimistic updates

### Technical Debt Areas

- **Mixed Layout Patterns**: Desktop and mobile use different strategies
- **Component Responsibilities**: Progress bar handling both display and
  navigation
- **State Synchronization**: Multiple sources of truth for current page state
- **DOM Manipulation**: Complex manual DOM updates for accordion content

### Integration Points

- **SurveyJS Integration**: Custom wrapper handles lifecycle and events
- **Database Persistence**: Real-time saving through Remix actions
- **Responsive Design**: Tailwind CSS with breakpoint-based layouts
- **Question Structure**: 88 questions across 7 sections with help content

### Data Flow Dependencies

- **Server State**: `assessment.currentPageIndex` and `assessment.surveyData`
- **Client State**: Survey component model and UI state
- **Navigation State**: Progress bar current index and answered questions set
- **Section State**: Derived from current question metadata

### Critical Integration Points

- **Survey Component**: Receives `surveyJson` from `convertToSurveyJsFormat()`
- **Progress Bar**: Uses question metadata for section identification
- **Section Display**: Depends on current question's section property
- **Navigation**: Callbacks flow from progress bar → route → survey component

This diagnostic reveals that the issues stem from inconsistent layout patterns,
missing navigation features, and complex DOM manipulation rather than
fundamental architectural problems. The codebase is well-structured but needs
targeted fixes to the identified components.
