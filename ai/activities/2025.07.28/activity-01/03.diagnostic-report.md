# Question Groups Implementation - Diagnostic Report

## Executive Summary

This diagnostic report analyzes the current ESG Assessment platform architecture to determine the implementation requirements for Question Groups functionality. The analysis covers the existing codebase structure, data flow patterns, UI components, and integration points that will be affected by the new feature.

## Current Architecture Analysis

### 1. Question Configuration System

**File:** `app/utils/assessment-questions.ts`

**Current Structure:**
```typescript
export interface QuestionConfig {
  questionId: string
  name: string  
  type: 'radiogroup' | 'checkbox' | 'text' | 'rating' | 'boolean'
  title: string
  help?: string
  reporting?: string
  docs?: string
  section: string
  choices?: string[]
  isRequired: boolean
  score: number
}
```

**Key Findings:**
- ✅ **Strong Foundation**: The interface is well-structured and extensible
- ✅ **v2.0 Enhancement**: Recently updated with semantic help fields (help, reporting, docs)
- ✅ **Markdown Support**: Titles and help content support markdown formatting
- ❌ **Missing Group Support**: No `type: 'group'` or `parentQuestionId` fields
- ❌ **No Umbrella Logic**: No filtering or processing for non-answerable questions

**Current Question Distribution:**
- **88 total questions** across 7 sections (SEZIONE 0-VI)
- **Question Types**: Primarily `radiogroup` and `text`
- **Section Structure**: Questions organized by ESG compliance sections

### 2. SurveyJS Integration Layer

**File:** `app/utils/assessment-questions.ts` - `convertToSurveyJsFormat()`

**Current Implementation:**
```typescript
export function convertToSurveyJsFormat(questions: QuestionConfig[]) {
  return {
    pages: questions.map((q) => ({
      elements: [{
        type: q.type,
        name: q.name,
        title: q.title,
        isRequired: false, // Fixed to false for navigation freedom
        choices: q.choices,
        // Custom properties preserved:
        questionId: q.questionId,
        section: q.section, 
        help: q.help,
        reporting: q.reporting,
        docs: q.docs,
        score: q.score
      }]
    })),
    showProgressBar: 'off',      // Uses custom progress bar
    showNavigationButtons: true,  // Enables Previous/Next
    showQuestionNumbers: 'off',   // Clean UI without numbers
    goNextPageAutomatic: false    // Manual navigation control
  }
}
```

**Key Findings:**
- ✅ **One Question Per Page**: Perfect foundation for umbrella question pages
- ✅ **Custom Progress Bar**: Already disabled SurveyJS built-in progress
- ✅ **Custom Properties**: Preserves metadata needed for umbrella questions
- ❌ **No Group Filtering**: All questions become survey pages regardless of type
- ❌ **No Umbrella Page Logic**: No special handling for navigation-only pages

**Required Changes:**
1. Filter `type: 'group'` questions to create navigation-only pages
2. Add umbrella question title injection to sub-question pages
3. Update page generation logic for group hierarchies

### 3. Progress Bar Components

**Current Progress Logic:**
```typescript
const getProgressDotStatus = (index: number, questionId: string) => {
  const isAnswered = answeredQuestions.has(questionId)
  const isCurrent = index === currentIndex
  
  if (isAnswered && isCurrent) return 'answered-current'
  if (isAnswered) return 'answered'
  if (isCurrent) return 'current'
  return 'unanswered'
}

const getProgressDotStyles = (status: string) => {
  switch (status) {
    case 'answered': return 'bg-green-500 border-green-500 rounded-full'
    case 'current': return 'bg-transparent border-primary ring-4 rounded-full'
    case 'unanswered': return 'bg-gray-300 border-gray-300 rounded-full'
  }
}
```

## Compatibility Analysis

### ✅ Strengths (What Works Well)
- **Extensible Architecture**: Interface design supports new question types
- **One-Question-Per-Page**: Perfect foundation for umbrella question navigation
- **Custom Progress System**: Already bypasses SurveyJS built-in progress tracking
- **Metadata Preservation**: Custom properties flow through entire system
- **DOM Injection System**: Robust framework for UI customization

### ⚠️ Challenges (What Needs Attention)
- **Progress Calculations**: Currently count all questions uniformly
- **Question Type Filtering**: No existing logic to handle different question types differently
- **Parent-Child Relationships**: No current system for question hierarchies
- **Umbrella Page Rendering**: No template for pages without input elements

### ❌ Blockers (What Must Be Fixed)
- **Interface Extension**: Must add `type: 'group'` and `parentQuestionId` fields
- **SurveyJS Page Logic**: Must filter group questions in page generation
- **Progress Bar Status**: Must add umbrella question status and styling
- **Answer Tracking**: Must exclude umbrella questions from completion logic
